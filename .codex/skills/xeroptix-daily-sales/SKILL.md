# Xeroptix 每日获客 · V3.3

将此技能作为统一执行说明。用户后续明确修改高于本版；历史草案、奇偶作业日、不补邮箱、90分硬门槛均已废止。不得覆盖历史事实或自动上调历史分数。

## 先理解执行边界

- 遵循：**LeadContact筛公司 → 企业研究与销售判断 → 合格公司补目标人及邮箱 → 原模式开发信 → 用户人工发送**。
- 每天都搜索、研究和准备邮件。把85分当优先排序，不能要求未补联系人/邮箱的公司先到85分才允许补联络。
- 每日目标：新增10家集团候选，优先推进5家存量高潜，争取3封具备适用邮箱的首次人工发送邮件包。目标不是无条件承诺，不凑数、不伪造需求。
- 日预算计划100积分、硬上限200积分，含搜索/档案/邮箱合计。每日高级搜索最多1页；不查电话。预算细则见[API与预算](references/api-budget.md)。
- 只生成正文和邮件包。禁止自动或批准后代发、转发、连接请求、InMail和测试邮件；不统一启用4–6天四连跟进。
- 此技能不自带时钟或永久服务器。已有每日09:00 Asia/Shanghai Work任务是唯一调度；不要新建重复任务、本地第二调度或自动迁移腾讯。

## 1. 预检并恢复真实状态

1. 用Asia/Shanghai确定当天日期，记录真实起止时间；禁止把触发时刻当完成时间。
2. 读取当前统一客户主库和唯一运行台账，核历史发送、用户确认转发、拒绝、退信、交接；版本保护写回。入口见runtime引用。
3. 运行`python <skill>/scripts/run.py preflight --env <private-env>`。预检不联网、不扣费；不要打印.env或密钥。
4. 确认原预算数据库和当天请求可访问。丢失状态时先恢复；不能新建空账本绕过200上限或假称历史去重为0。
5. 只使用本技能脚本/同一运行程序的事务账本发起付费请求。禁止另用curl或其他进程绕过账本。凭据未配置、余额读不到或账目不明时停止付费，继续可完成的公开研究并报缺口。
6. 如用户仅要求测试/模拟且禁止积分，运行`dry-run`或`preflight`，不运行discover/finalize；余额接口也仅在明确需要免费联网测试时调用。

## 2. LeadContact发现目标公司

1. 选择已审核的单国、行业、规模和当地角色关键词组合。API员工搜索不是已证实的公司自由关键词接口；只用支持字段，不臆造参数。
2. 运行`run.py discover --env <private-env>`。相同日期、相同请求复用成功结果，禁止第二页和为低产出反复重搜。
3. 按公司名聚合人员，再核官网/法人/集团；20个人不等于20家公司或20个合格账户。分开计返回人员、公司名称、核验公司、合格候选和集团新增。
4. 读取`run.py queue --env <private-env>`。`awaiting_native_research`表示等待当前Work研究接力，不是研究完成。
5. 优先处理有具体产品/工序的OEM、制造终端及独立渠道池。低产出不放回销售岗/同行/排除市场。无可用LeadContact时标注未调用；公开搜索后备不冒充LeadContact结果。

## 3. 研究企业并作销售判断

1. 使用当前Work可用研究工具，实际读取官网产品、工序、案例、招聘和新闻；必要时核参与方、行业媒体、官方公众号正文。摘要/搜索片段不能冒充已读原文。
2. 核市场、企业角色、已知集团关联、产品/场景、现有AI/供应商、互补方向。只在有证据时写采购/预算/未满足需求。
3. 以具体任务提出探索假设。无近期新闻、人数未知、缺第二篇同事件报道、尚未确认全部芯片接口，不单独阻断探索。明显不适配、同质排除或无任何合理相关任务则停止补联络。
4. 不因未检出视觉/AI而写“没有系统”或“干净目标”；填未核实。已有AI不是自动扣分项。
5. 保存初评事实、来源、缺项及原因；联系人与邮箱未知计0，不推满分、不按75分重新归一化。合格公司才能进入下一步。
6. 记录事件实际日期、官方首次发布、当前页面日期；转载和旧案不能刷新时效，未来活动不能写已发生。招标单独项目池核截止和资质。

## 4. 二次核验现任并补邮箱

1. 从LeadContact结果中选择相关质量/生产/工厂/技术/自动化/工程/采购负责人，中小企业老板可用；渠道池按合作/工程交付职责选择，不能机械排除合作商务负责人。
2. API的`currentTitlesOnly`和`isCurrent`只作线索。实际读取官网团队/任命或原始个人职业资料，核姓名、企业、职位及时间。保留URL、核验日期和API冲突。
3. 官网当前团队支持在任时，可解释API false为冲突记录并保留；明确离职/其他现任雇主冲突无法消除则待核，不付费补邮箱。不能只凭TheOrg或搜索摘要宣称原始资料已核实。
4. 近30天个人活跃优先，31–90天补充；个人和企业活动分别记录。任职180天是代理信号，不等于近30天活跃，不设活跃硬门槛。
5. 准备`review.json`：包含`account`、`person`、`employment_evidence`、`retrieved_urls`、`copy`和`evidence_reviewed:true`。完整字段及边界见runtime。先写合格正文，避免查邮箱后因正文缺失丢失工作。
6. 运行`run.py finalize --env <private-env> --input <private-review.json>`。脚本重核业务门槛、历史、现任和预算，再逐个查邮箱、最终评分、保存正文。
7. 拒绝免费个人邮箱、invalid、unknown/catch-all未核清、归属冲突及用途不适配地址。valid不等于送达；不查询电话、不发送验证信。
8. 同集团通常一人首触。补联络失败保存为needs_contact；不得把缺邮箱正文计可发送邮件。复用已有近期API结果，缓存标日期，不称新核验。

## 5. 写信、交付、状态保存

1. 按原模式写自然英文，通常100–160词；用户另指定语言则遵循。一项真实事实、一个任务、一个切口、一个具体问题。没有真实紧迫性不编Why Now。
2. 区分优先与探索，不把探索称高意向。输出公司/池/通道/最终分数、负责人/邮箱/来源、主题、完整正文及附件状态；无附件不写已附。
3. 固定签名：Alen Wang / Xeroptix / AlenWang@xeroptix.com / https://xeroptix.com。
4. 将本地结果和Library同ID台账/主库同步，保留版本、来源和冲突；写回失败就标未同步，不宣称完成。不得公开上传私人数据库/客户邮件/密钥。
5. 平日交邮件包及一行达成/阻塞；无邮件时简述实际研究、主要阻塞、已做补救。周五交完整台账及分池漏斗、预算和下周建议，防重复交付。
6. 仅用户明确报告或邮箱证据后更新状态。reported_sent/reported_forwarded与邮箱SENT、送达、回复、有效线索、商机分开；用户转发确认有效用于去重但不代表送达。PATEO已交接，不重建、不催办；历史冻结继续执行。
7. 权重、市场、预算、发送权限等业务冲突先列明请用户确认；不自动改规则或把反馈训练成已生效新权重。

## 自动运行验收

确认技能已保存、原09:00任务启用、凭据和预算数据库可读、Work研究工具可用、原主库/台账可读，再报告“配置就绪”。只有真实完成研究、邮件包保存和台账写回后才报告本轮完成。请求即时运行成功仅代表请求受理。当前会话进程不等于24小时托管；后续腾讯独立部署另行配置模型后端、迁移状态并切换唯一调度主体。
