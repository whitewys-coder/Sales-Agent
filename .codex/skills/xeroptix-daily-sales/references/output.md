# 开发信与结果交付

## 邮件

沿用自然英文100–160词，用户另指定语言则遵循。四个要素：实际读取的企业/产品/工序事实；一个待确认任务；一个相关合作切口；一个具体低门槛问题。缺近期事件就解释长期场景探索，不编紧迫性、预算、痛点已发生或采购意愿。

按角色：质量关注检查/追溯，生产关注换型/人工核验，技术关注数据/接口/端侧部署，采购关注供应商能力和边界，OEM关注一个模块化评估，渠道关注工程交付和互补合作。不能把“标配模块”“合作分成”写成已获授权承诺。

已有Keyence/Cognex等不全盘否定或声称替换；不承诺未实测精度、节拍、收益。<1MB只指证实运行时组件，不是任意模型。未认证不称车规。数天开发、漏检率<1%、604轮/3066步骤、30天试用、4–6周PoC等必须有能力证据/商务授权和适用范围才引用，样本结果不泛化。

签名固定：
```
Alen Wang
Xeroptix
AlenWang@xeroptix.com
https://xeroptix.com
```

只准备最终文本，附件无则明确无；未创建邮箱草稿不虚构draft_id。发送统一由用户人工操作，任何“批准”都不改变禁止代发。人工报告时间/说明保留来源，不填虚假的message_id。拒绝/退订停止，退信冻结，无回复通常30–60天或新事件再评估，不统一四连跟进。

## 日常与周五

平日每个可供人工发送包：批次ID、公司/国家/池、通道与最终分、负责人/职位/邮箱及来源、简短切口、主题、完整正文、附件状态。缺邮箱草案另列不可发送；重复展示旧草稿不计新增。末尾一行实际新增集团/邮件包/积分与主要阻塞。
无邮件最多三行：实际研究、主要阻塞、已完成补救。不要反复只报待核，不输出每日全量CSV让用户手工保存。

后台完整留存：日期/真实起止、预设、请求次数、预算预留/实扣/未知、返回人员/公司/集团数、初评/最终分与证据、各阶段产出、阻塞和写回状态。
周五09:00同任务一次完整台账：本周新增集团、研究合格、补人/邮箱、优先/探索包、实际发送/用户报告、真实回复/拒绝/退信、分池漏斗、预算、来源效率、下周3–5动作。分母/观察窗口缺失不算转化率；研究或发件不是有效线索/商机/订单。
